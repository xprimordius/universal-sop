<summary><b>SP.1 — MagNet (Magnetic Visual Engagement Protocol)</b></summary>

### Full Name
**MagNet — Magnetic Visual Engagement Protocol**

### Acronym Origin
"Mag" (magnetic) + "Net" (network of visual cues). Originally MN.1-MN.4 in early drafts.

### Core Purpose
Make every output visually engaging and scannable so users can extract value in seconds without reading paragraphs.

### Scope (Where It Applies)
- Every section of every output
- Every table, header, list
- Every confirmation, conclusion, foresight block

### Sub-Components

|:---:|------------|----------|
| MN.1 | Emojis far left | Every table row starts with an emoji column on the left |
| MN.2 | Tables over paragraphs | Comparisons, lists, status reports → table format |
| MN.3 | Headers with emoji anchors | Section headers use emoji prefixes for visual landmarks |
| MN.4 | Scannable structure | Bullets, numbered lists, short sentences |

### When Triggered
Always-On. Every section of every output. No exceptions.

### Failure Mode If Skipped
Wall-of-text outputs. User has to read everything to find key points. Alan's #1 trigger: "too wordy" / "not coherent."

### Token Cost
~0 additional (structural, not content). Saves time downstream.

<summary><b>SP.3 — TTE (Token Threshold Engine)</b></summary>

### Full Name
**TTE — Token Threshold Engine**

### Acronym Origin
Pure description — Token (the budget unit) + Threshold (decision boundaries) + Engine (the math system).

### Core Purpose
Mathematical fuel budget so sessions don't crash mid-task. Math-based, not judgment-based.

### Scope
- Every output (tracking)
- Every session (cumulative)
- Every long-running task (forecasting)

### Sub-Components
| 🆔 | 🏷️ Threshold | 📊 Range | 🎯 Action |
|:---:|------------|---------|----------|
| GREEN | Healthy | <108K / 200K | Full operations, all SubSOPs active |
| YELLOW | Warning | 108-130K | Abbreviated validation, plan checkpoint |
| RED | Critical | 130-141K | Checkpoint NOW, cache all state, no new deliverables |
| CRITICAL | Emergency | >141K (theoretical only) | Emergency cache dump |

### The Math (Why CRITICAL Is Unreachable)
- 200K context window
- 59K emergency reserve (locked)
- 130K + 59K = 189K (still <200K)
- So if RED triggers at 130K and emergency reserve activates, we never hit 200K

### Companion: LTM (Live Token Monitor)
Visible after EVERY section showing:
- 📝 Section tokens
- 📦 Step cumulative
- ⏱️ Session cumulative / 200K
- 🔋 Remaining
- Status emoji (🌱 GREEN / 🟡 YELLOW / 🔴 RED)

### When Triggered
- Estimate BEFORE every output (in header)
- LTM after every section
- Status check every wrap-up

### Failure Mode If Skipped
Session runs out of fuel mid-task. Work gets lost. AI doesn't warn before crash.

### Token Cost
~200 tokens per LTM × ~8-10 sections = ~2K per output. Worth it.

### Related Protocols
- EN.1 Output Skeleton pre-places LTM blocks
- SP.10 SCC verifies LTM presence before send

</details>

<summary><b>SP.24 — RAE (Recommendations At End)</b> ⭐ NEW 2026-05-22</summary>

### Full Name
**Recommendations At End Protocol**

### Acronym Origin
**R**ecommendations **A**t **E**nd. Every actionable next-step suggestion is funneled into a single block at the very end of the output — never inline, never scattered.

### Status
✅ **MANDATORY** in `MANDATORY_TIGHT_LOOP.md` v1.6 as item #11. Pulse Check P10 enforces presence. Validator VL.11 greps for the literal `🎯 RECOMMENDATIONS (SP.24 RAE)` marker.

### Origin
2026-05-22 Alan: *"All recommendations should be at the very end, in a very simple way to understand and pick. embed this into the SOP so we don't miss it. if it needs to be named an agent or protocol so be it."*

### Core Purpose
Eliminate "scattered recommendations" anti-pattern. Past outputs had recommendations buried inline mid-document, in Foresight blocks, in SIR insights, AND in closing summaries — user had to scan everywhere to find what to pick next. RAE funnels every actionable suggestion into ONE pickable list at the end.

### Format

```
🎯 RECOMMENDATIONS (SP.24 RAE)
Pick a number (or describe alternative):

1. <Option A short> (XS — 5 min)
2. <Option B short> (S — 15 min)
3. <Option C short> (M — 45 min)
4. <Option D short> (L — 2h+)

⭐ Recommended: <#N>  (if one is obviously best)
```

**Rules:**
- LAST visible content of the output (after Sync Status)
- Max 5 options, each ≤ 12 words
- Effort tag mandatory: XS (<10min) / S (10–30min) / M (30min–2h) / L (>2h)
- If only one is obviously best: prefix with ⭐ and list first
- If NO recommendations apply: explicit `(none — task complete, awaiting direction)` line
- **No inline recommendations elsewhere** — Foresight may name risks, SIR may surface insights, but actionable picks go only here

### When Triggered
- Every `MODE: OUTPUT-STANDARD` / `MODE: OUTPUT-COMPLEX` output
- Every CONVERSATION-mode output that surfaces a decision point
- Skipped only when output is pure status (e.g., "✅ committed, nothing to decide")

### Pulse Check Item
**P10 — RAE present (SP.24)** in `MANDATORY_TIGHT_LOOP.md` v1.6 10-item Pulse Check.

### Validator Check
**VL.11** in `scripts/validator.sh` — greps output for literal `🎯 RECOMMENDATIONS (SP.24 RAE)` block.

### Failure Mode If Skipped
Original Alan frustration 2026-05-22: *"without these constant user prompts to remind coherence / adherence"* — recommendations scattered everywhere = decision overhead + missed options = user has to keep prompting for clarity. RAE collapses this into one scan.

### Token Cost
~100–250 tokens per output (5-row table or numbered list with effort tags).

### Related Protocols
- **SP.7 Insights** — observations (present-adjacent). RAE = actions (forward).
- **SP.9 FE (Foresight)** — predictions. RAE consolidates the actionable subset of those predictions.
- **SP.17 SIR** — system improvements. RAE picks up the actionable ones.
- **EN.1 Output Skeleton** — RAE is the FINAL mandatory slot.
- **EN.4 Pulse Check** — P10 enforces.

### Owner
- **Per-output:** AI self-check (Pulse Check P10) + Validator VL.11 at commit time
- **Meta-level:** Chiron (`agents/chiron.md`) — monthly audit ensures RAE compliance ≥90%

| Layer | Where | What |
|---|---|---|
