# Building the ultimate Claude project instructions framework

> [!info]- Conversation summary
> **Conversation Overview**
> 
> Alan is building a comprehensive sales training system using Claude as an AI coaching tool. He provided 13 training files (labeled 6.1 through 6.13) covering a complete high-ticket consultative sales methodology. The core request was to read all files sequentially, synthesize each lesson individually, then integrate everything into a unified master instruction set for a Claude project — with Constantine's Sales Structure (6.13) serving as the immutable architectural core that all other lessons enrich but never override.
> 
> Claude read all 13 files in sequence and produced two deliverables: a full synthesis document with lesson-by-lesson breakdowns and annotated framework, and a standalone copy-paste-ready project instructions file. Alan then asked for a critical review of those instructions, and Claude identified 12 specific gaps — including a missing certainty reframe script as the entry point for fear handling, a collapsed smokescreen diagnostic that should be three distinct scripts chosen by context, a blurred distinction between the Escape (push) and Commitment (pull) phases, the loss of the "price drop" anchoring mechanism, missing frame control and silence/momentum principles, an incomplete list of fear sources, and the absence of a deposit diagnostic principle. A corrected final version (v2) was produced incorporating all 12 fixes, with Constantine's structure kept intact and all tactical depth from lessons 6.1–6.12 woven in at the correct phases.
> 
> The system is built around Constantine's four-phase structure: Intro, Discovery (11 sequential sub-phases), Pitch, and Close. The close follows a strict objection handling hierarchy — smokescreens first, then money, then fear, then logistics, then partner/responsibility close — and the instructions emphasize that jumping to fear before checking money is one of the most common and costly mistakes closers make. Key teaching principles include: frames over scripts, exact language over concepts, diagnosis before prescription, and always closing with binary yes/yes options rather than yes/no. The self-analysis and auto-improvement protocol is baked into the instructions so Claude assesses framework alignment, tactical depth, specificity, diagnosis accuracy, and actionability after every substantive coaching exchange, then suggests the highest-leverage next focus area.
> 
> Alan's working name for the prime model is "Constantine's training" and he refers to the supporting lessons (6.1–6.12) as reference points for deeper context. His explicit instruction is that Constantine's framework can be added to and filled in, but nothing can be deleted from it. The project is designed to function as both a practical coaching tool for live call analysis and role-play, and as a teaching system that develops students into proficient masters rather than script-readers.
