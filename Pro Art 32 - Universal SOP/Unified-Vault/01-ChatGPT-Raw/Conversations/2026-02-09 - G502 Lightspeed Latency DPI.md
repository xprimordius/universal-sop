- Average wait: **~2 ms**

## Why “FPS sync” intuition feels right — but isn’t

You’re thinking:
> “If my game is 240 FPS (~4.17 ms), why not match polling to that?”

The problem is **phase alignment**.

### Mouse polling and game frames are **not synchronized clocks**
- The mouse doesn’t know when a frame starts
- The game doesn’t know when the mouse last reported

So at 250 Hz:
- Your input might arrive **just after** a frame started
- It then waits **almost a full frame** to be used
- That stacks with the 4 ms polling delay

At 1000 Hz:
- Even if it misses a frame boundary, it’s only late by ~1 ms max

---

## Key concept: **quantization delay**
Lower polling = coarser time “buckets”

```
1000 Hz → buckets every 1 ms
250 Hz  → buckets every 4 ms
```

Your motion is continuous, but it gets **snapped** to the next bucket.

More snapping = more delay.

- Better consistency frame-to-frame
